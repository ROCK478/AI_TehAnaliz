## 1. Регистрация с несуществующей почтой (например `ff@ff.e`)

**Проблема.** Валидация e-mail проверяла лишь наличие символов `@` и `.` в строке,
поэтому проходили любые фиктивные адреса.

**Решение.**
- Подключена библиотека [`email-validator`](https://pypi.org/project/email-validator/)
  (добавлена в `requirements.txt`).
- При регистрации проверяется:
  1. корректность **формата** адреса (включая допустимый домен верхнего уровня);
  2. **реальное существование почтового домена** — наличие DNS-записей MX/A
     (`check_deliverability=True`).
- Адрес нормализуется (`valid.normalized`) перед сохранением в БД.

**Где:** `app.py` — блок `errors` в маршруте `/register`; импорт
`from email_validator import validate_email, EmailNotValidError`.

**Конфигурация:** в `config.py` добавлен флаг `EMAIL_CHECK_DELIVERABILITY`
(по умолчанию включён). Отключается переменной окружения
`EMAIL_CHECK_DELIVERABILITY=0` — это нужно автотестам, работающим без сети.

**Проверка:**
- `ff@ff.e` → «The domain name ff.e does not exist» → регистрация отклонена;
- `ff@nonexistent-domain-12345.ru` → отклонена;
- `test@gmail.com` → принята.

> Ограничение: проверяется существование **домена**, но не конкретного ящика.
> Гарантировать живой ящик можно только письмом со ссылкой подтверждения
> (double opt-in) — при необходимости можно добавить отдельно.

## 2. Текст выходит за пределы окошка в «Дневнике инвестора»

**Проблема.** Длинный текст заметки (особенно длинные слова/строки без пробелов)
не переносился и вылезал за границы панели.

**Решение.** В `static/css/style.css` добавлены классы:

```css
.entry-title{min-width:0;overflow-wrap:anywhere}
.entry-body{white-space:pre-wrap;overflow-wrap:anywhere;word-break:break-word}
```

и применены в `templates/diary.html`: заголовок записи — `.entry-title`,
текст заметки — `.entry-body`.

- `overflow-wrap:anywhere` / `word-break:break-word` — перенос любых длинных слов;
- `min-width:0` — позволяет заголовку сжиматься внутри flex-контейнера;
- бонус: `white-space:pre-wrap` — в заметках теперь сохраняются переводы строк,
  введённые пользователем в textarea.

## 3. Усиление требований к паролю

**Проблема.** Единственное требование — длина от 6 символов; проходили
простейшие пароли вида `123456`.

**Решение.** В `app.py` добавлена функция `password_errors(password)`.
Пароль обязан содержать:

| Требование | Проверка |
|---|---|
| Минимум **8 символов** | `len(password) >= 8` |
| Строчная буква (лат./кир.) | `[a-zа-яё]` |
| Заглавная буква (лат./кир.) | `[A-ZА-ЯЁ]` |
| Цифра | `\d` |
| Спецсимвол (`!`, `?`, `#` и т.п.) | `[^A-Za-zА-Яа-яЁё0-9\s]` |

Каждое нарушение выводится отдельным flash-сообщением, чтобы пользователь
понимал, что именно исправить.

**Фронтенд:** в `templates/register.html` обновлена подсказка у поля
(«минимум 8 символов: заглавная и строчная буквы, цифра и спецсимвол»)
и добавлен атрибут `minlength="8"`.

## 4. Кнопка «Закрыть» в политике конфиденциальности

**Проблема.** Страница `/privacy` открывается из формы регистрации в новой
вкладке (`target="_blank"`), но не имела способа вернуться/закрыться.

**Решение.** В `templates/privacy.html` внизу страницы добавлена кнопка
**«Закрыть»**:

1. сначала пытается закрыть вкладку (`window.close()` — работает для вкладок,
   открытых по ссылке);
2. если браузер не разрешил закрытие — возвращает назад по истории
   (`history.back()`);
3. если истории нет (страница открыта напрямую) — переходит на главную.

## 5. Подтверждение удаления записи из дневника

**Проблема.** Кнопка «Удалить» сразу отправляла POST-запрос — запись удалялась
безвозвратно одним случайным кликом.

**Решение.** В `templates/diary.html` на форму удаления добавлен обработчик:

```html
onsubmit="return confirm('Удалить запись «{{ e.title }}»? Это действие необратимо.');"
```

Браузер показывает диалог подтверждения с названием записи; при отмене
запрос не отправляется.
